## 一、Hook 漏洞（7 个问题）

### H1. routing-gate.js 不校验 TASK_ROUTE 内容

| 项目 | 内容 |
|------|------|
| **问题** | Hook 只检查 `.routing-confirmed` 文件是否存在，不校验 TASK_ROUTE 的格式、目标组、任务摘要。用户手动确认格式错误的 TASK_ROUTE 后，Hook 直接放行。 |
| **风险** | 中 — 任务被路由到错误的组，但不会导致系统崩溃 |
| **修复方案** | marker 文件写入结构化内容（`target_group\|task_summary`），routing-gate 校验内容与当前 Agent 调用是否匹配 |
| **优先级** | P2 |
| **预计工时** | 0.5 天 |

```javascript
// 修复思路：marker 文件内容化
// 创建时写入：
fs.writeFileSync(markerPath, `${targetGroup}|${taskSummary}`, 'utf8');

// 校验时读取并比对：
const [savedGroup] = fs.readFileSync(markerPath, 'utf8').split('|');
if (savedGroup !== expectedGroup) {
  console.error('[RoutingGate] Group mismatch');
  return { exitCode: 2 };
}
```

### H2. marker 文件残留（崩溃/遗忘导致未清理）

| 项目 | 内容 |
|------|------|
| **问题** | routing-cleanup.js 只在 `summary.md` 写入时删除 marker。如果 Claude 崩溃、会话中断、或遗忘写 summary，marker 残留，下次会话被错误放行。 |
| **风险** | 高 — 下一个任务跳过路由直接执行 |
| **修复方案** | marker 文件写入时间戳，routing-gate 检查时超过 24 小时自动删除 |
| **优先级** | P1 |
| **预计工时** | 0.5 天 |

```javascript
// 修复思路：marker 带时间戳 + 过期检查
function isRouteConfirmed() {
  const markerPath = getMarkerPath();
  if (!fs.existsSync(markerPath)) return false;

  const content = fs.readFileSync(markerPath, 'utf8').trim();
  const ts = parseInt(content.split('\n')[0], 10);
  if (Date.now() - ts > 24 * 60 * 60 * 1000) {
    fs.unlinkSync(markerPath);
    return false;
  }
  return true;
}

// 创建 marker 时：
fs.writeFileSync(markerPath, `${Date.now()}\n${targetGroup}`, 'utf8');
```

### H3. auditor-isolation.js 无法防语义级暗示

| 项目 | 内容 |
|------|------|
| **问题** | 审计师 A 可以在报告中用代码示例、测试用例、注释等方式隐晦暗示审计 B 的关注方向。Hook 只检查 prompt 中是否包含对方文件名，不解析语义。 |
| **风险** | 低 — LLM 没有串通动机，但 prompt 注入攻击可能利用此漏洞 |
| **修复方案** | 不在 Hook 层解决（太脆弱），改为：(1) 审计师 tools 无 Bash（已实现），(2) 交叉质疑时主控做脱敏中转（已实现），(3) 增加 prompt 注入检测 Hook |
| **优先级** | P3 |
| **预计工时** | 1 天（prompt 注入检测） |

### H4. session-log-check.js 不校验日志内容

| 项目 | 内容 |
|------|------|
| **问题** | Hook 只检查文件路径是否以 `session-log.md` 结尾，不解析 markdown 表格结构。Claude 可以写一行"已更新日志"蒙混过关。 |
| **风险** | 中 — 日志不完整影响会话可追溯性和知识提取 |
| **修复方案** | 增加宽松校验：检查是否包含 `SESSION_LOG` 关键词 + 至少一行表格数据（`\| \d+ \|`） |
| **优先级** | P2 |
| **预计工时** | 0.5 天 |

```javascript
// 修复思路：内容校验
function validateLogContent(content) {
  const hasHeader = content.includes('SESSION_LOG');
  const hasDataRow = /\|\s*\d+\s*\|/.test(content);
  return hasHeader && hasDataRow;
}

// 在 isSessionLogUpdate 中增加：
if (isSessionLogUpdate(toolName, filePath)) {
  const content = fs.readFileSync(filePath, 'utf8');
  if (!validateLogContent(content)) {
    console.error('[SessionLogCheck] BLOCKED: Log content invalid');
    return { exitCode: 2 };
  }
  deletePendingMarker();
  return { exitCode: 0 };
}
```

### H5. Hook 异常时默认放行

| 项目 | 内容 |
|------|------|
| **问题** | 所有 Hook 的 catch 块都返回 `exitCode: 0`（放行）。如果 Hook 脚本崩溃，防护失效但工具调用被放行。 |
| **风险** | 高 — 安全关键 Hook（auditor-isolation）崩溃 = 隔离失效 |
| **修复方案** | 对安全关键 Hook（routing-gate、auditor-isolation、code-gate）异常时返回 `exitCode: 2`（阻断）；对行为引导 Hook（sop-reminder、session-log-check）异常时放行 |
| **优先级** | P1 |
| **预计工时** | 0.5 天 |

```javascript
// 修复思路：分级异常策略
const BLOCK_ON_ERROR_HOOKS = ['routing-gate', 'auditor-isolation', 'code-gate'];

function run(rawInput, hookName) {
  try {
    // ... 业务逻辑
  } catch (error) {
    console.error(`[${hookName}] Error: ${error.message}`);
    const exitCode = BLOCK_ON_ERROR_HOOKS.includes(hookName) ? 2 : 0;
    return { exitCode };
  }
}
```

### H6. session-log-check.js 的 marker 过期导致日志缺失

| 项目 | 内容 |
|------|------|
| **问题** | `.session-log-pending` marker 过期时间 30 分钟。如果 Claude 在 30 分钟内未更新日志，marker 过期，下次 Agent 调用不被阻断，日志永久缺失。 |
| **风险** | 中 — 日志缺失影响会话完整性 |
| **修复方案** | 过期时输出警告（不静默清理），延长过期时间到 60 分钟，或改为"过期后重新创建 marker" |
| **优先级** | P2 |
| **预计工时** | 0.5 天 |

```javascript
// 修复思路：过期时重新创建而非静默清理
if (age > MARKER_EXPIRY_MS) {
  console.error(`[SessionLogCheck] WARNING: Marker expired. Recreating.`);
  createPendingMarker(); // 重新创建，继续阻断
  return true; // 仍然视为 pending
}
```

### H7. 没有 Bash 命令监控 Hook

| 项目 | 内容 |
|------|------|
| **问题** | 10 个 Agent 有 Bash 工具。恶意 prompt 注入可能让 Agent 执行 `rm .claude/.routing-confirmed` 删除标记文件，绕过路由门禁。当前没有 Hook 监控 Bash 命令。 |
| **风险** | 低 — Agent 没有动机删除标记，但 prompt 注入可利用 |
| **修复方案** | 新增 `bash-guard.js` Hook，拦截包含 `.claude/` 路径的删除操作 |
| **优先级** | P3 |
| **预计工时** | 0.5 天 |

```javascript
// 新增 .claude/hooks/bash-guard.js
const DANGEROUS_PATTERNS = [
  /\.claude\/.*routing-confirmed/,
  /\.claude\/.*session-log-pending/,
  /rm\s+.*\.claude\//,
];

function run(rawInput) {
  const input = JSON.parse(rawInput);
  if (input.tool_name !== 'Bash') return { exitCode: 0 };

  const command = input.tool_input?.command || '';
  const matched = DANGEROUS_PATTERNS.filter(p => p.test(command));

  if (matched.length > 0) {
    console.error(`[BashGuard] BLOCKED: Dangerous command: ${command}`);
    return { exitCode: 2 };
  }
  return { exitCode: 0 };
}
```

## 二、流程缺口（8 个问题）

### P1. 紧急通道缺少兼容性验证

| 项目 | 内容 |
|------|------|
| **问题** | 紧急通道 3 步跳过架构审计和完整回归。如果紧急修复是升级第三方库，可能破坏兼容性。补审在 24 小时后才触发，存在时间窗口风险。 |
| **修复方案** | 紧急通道 QA 步骤强制运行兼容性测试矩阵（所有直接调用该库的函数） |
| **优先级** | P2 |
| **预计工时** | 1 天（更新 QA Agent prompt + 兼容性测试模板） |

### P2. SOP 强制"读"但不强制"做"

| 项目 | 内容 |
|------|------|
| **问题** | sop-reminder.js 阻断后要求读 SOP，但不验证 Claude 是否按 SOP 执行。Claude 可能读了 SOP 但在执行中跳过子步骤。 |
| **修复方案** | 在 Agent prompt 中增加"前置检查清单"，要求每个步骤输出 checklist 完成状态 |
| **优先级** | P3 |
| **预计工时** | 1 天（更新 20 个 Agent prompt） |

### P3. YAML 元数据无校验

| 项目 | 内容 |
|------|------|
| **问题** | 下游 Agent 读到元数据格式错误的文件（如日期 `2026-13-32`），没有定义异常处理策略。 |
| **修复方案** | 在 Agent prompt 中增加 Input Validation 步骤，校验 YAML 前置字段。校验失败时输出 `INPUT_VALIDATION_FAILED` 并停止。 |
| **优先级** | P3 |
| **预计工时** | 1 天（更新 Agent prompt + YAML 校验模板） |

### P4. 不落盘产出物无检查点

| 项目 | 内容 |
|------|------|
| **问题** | `fix-report.md`、`self-test.md`、`change-summary.md` 不落盘。Claude 崩溃时这些中间状态永久丢失。 |
| **修复方案** | 在 SOP 每步完成后自动保存 checkpoint（JSON），记录当前步骤号和关键产出。恢复时从 checkpoint 续接。 |
| **优先级** | P3 |
| **预计工时** | 2 天 |

### P5. KNOWLEDGE_WORTHY 无负反馈机制

| 项目 | 内容 |
|------|------|
| **问题** | 知识条目被错误提取后，没有自动降级机制。知识库可能膨胀。 |
| **修复方案** | 实现引用追踪 + 有效性比率：统计每个知识条目被引用后的任务成功率，低于 50% 自动标记为 `awaiting_verification` |
| **优先级** | P3 |
| **预计工时** | 2 天 |

### P6. 上下文遗忘无强制恢复机制

| 项目 | 内容 |
|------|------|
| **问题** | Claude 在长会话中可能遗忘早期步骤结论。session-log 存在但 Claude 可能不去读。 |
| **修复方案** | 主控在每次召唤 Agent 时，在 `commander_directive` 中附上 session-log 的关键摘要（不超过 200 字） |
| **优先级** | P2 |
| **预计工时** | 0.5 天（更新 CLAUDE.md 的调度指令模板） |

### P7. 交叉质疑无法防止系统性偏见

| 项目 | 内容 |
|------|------|
| **问题** | 两个审计师可能因训练数据相似而有相同的 severity 偏见（如都认为 SQL 注入 > XSS）。信息隔离不能打破趋同。 |
| **修复方案** | 在交叉质疑阶段增加"视角互换"问题：强制审计师从对方视角审查一轮，提供至少一个被低估的风险点 |
| **优先级** | P3 |
| **预计工时** | 1 天（更新 SOP 交叉质疑模板） |

### P8. 缺少"审计复议"机制

| 项目 | 内容 |
|------|------|
| **问题** | 程序员只能在 SOP Step 6 中拒绝审计建议，不能在 QA 验证后追溯审计结论。如果审计建议导致了不必要的修改，没有上诉渠道。 |
| **修复方案** | 在 QA 验证后增加可选的"审计复议"步骤，程序员可以请求总指挥复议审计结论 |

| **预计工时** | 0.5 天 |

## 四、架构局限（5 个问题）

### A1. 单实例共享文件系统，无法做到语义级隔离

| 项目 | 内容 |
|------|------|
| **问题** | 所有 Agent 共享同一个文件系统。审计师 A 的报告存在磁盘上，审计 B 理论上可以通过 Read 工具读到（虽然 Agent prompt 没有指示它这么做）。 |
| **修复方案** | 长期：分布式部署（不同 Agent 在不同容器中，通过消息队列通信）。短期：审计师 tools 无 Write（已实现），减少侧信道 |
| **优先级** | P4（长期） |

### A2. Hook 是单次调用级别，不检测跨调用组合攻击

| 项目 | 内容 |
|------|------|
| **问题** | Claude 可以通过"创建 marker → 调用 Agent → 删除 marker"的组合绕过路由门禁。单个 Hook 看不出问题。 |
| **修复方案** | 新增 `state-tracker.js` Hook，追踪从会话开始到当前的工具调用序列，检测异常模式 |
| **优先级** | P3 |
| **预计工时** | 2 天 |

### A3. Agent 没有代码执行能力，"实证推翻"名不副实

| 项目 | 内容 |
|------|------|
| **问题** | 审计师 tools 只有 Read/Grep/Glob，不能运行代码验证断言。所谓的"实证推翻"实际是"模型知识推翻"。 |
| **修复方案** | 给审计师增加受控的 Bash 能力（只允许 `python -c` 和 `node -e`，禁止文件系统操作），并在 prompt 中要求"每个断言必须先用代码验证" |
| **优先级** | P2 |
| **预计工时** | 1 天（更新 Agent prompt + 受控 Bash 实现） |

### A4. 上下文窗口是硬约束

| 项目 | 内容 |
|------|------|
| **问题** | 长会话中上下文被耗尽，导致遗忘、截断。SOP 文件每次步骤都要重新读取，浪费 token。 |
| **修复方案** | (1) session-log 自动压缩（旧任务摘要为一行），(2) SOP 关键约束提取到 Agent prompt（利用缓存），(3) 分层会话（子会话独立执行 SOP） |
| **优先级** | P1 |
| **预计工时** | 1 周 |

### A5. 知识条目无自动废弃机制

| 项目 | 内容 |
|------|------|
| **问题** | 知识条目只有 `next_review` 字段，过期后需要人工审查。没有基于引用效果的自动降级。 |
| **修复方案** | 实现引用追踪数据库 + 有效性比率计算 + 自动降级 |
| **优先级** | P3 |
| **预计工时** | 2 天 |
